# Product Requirements Document: Arcade Vibe

## 1. Overview
### Executive Summary
Arcade Vibe is a competitive, high-stakes prompt engineering platform styled as a retro arcade. Unlike traditional AI game builders, Arcade Vibe focuses on the "One-Shot" constraint: generating a fully functional, playable game from a single prompt. The platform gamifies the prompt engineering process through monthly themed competitions, model-based handicap multipliers, and a transparent leaderboard.

### Problem Statement
Most AI generation tools focus on multi-turn iteration or "chatting" to reach a result. This masks the true skill of prompt engineering and makes it difficult to objectively measure prompt quality, efficiency, and model portability.

### Value Proposition
For participants, it is a "competitive sport" to prove prompt engineering mastery. For players, it is a curated gallery of high-quality, AI-generated games categorized by the difficulty of the model used to create them.

---

## 2. Objectives
### Key Goals
- **Competitive Integrity:** Enforce a strict "one-shot" generation rule.
- **Model Agnostic Comparison:** Provide a standardized environment to compare game-gen capabilities across GPT, Claude, Deepseek, and GLM.
- **Educational Transparency:** Allow the community to dissect winning prompts to advance the field of prompt engineering.

### Success Metrics (KPIs)
- **Prompt Efficiency:** Average prompt length (lower is better for "Brevity" scoring).
- **Model Diversity:** Ratio of "Hard/Impossible" model usage vs. "Ultra/Cheater" models.
- **Portability Index:** Number of times a public prompt is "re-run" by other users on different models.
- **Retention:** Monthly Active Users (MAU) returning for new monthly theme cycles.

---

## 3. Target Audience
### User Personas
1. **The Prompt Architect:** Highly technical, experiments with system instructions and token efficiency. Aims for the top of the leaderboard using "Impossible" models.
2. **The Casual Arcade Player:** Browses the gallery, plays games in-browser, and votes on fun factor/polish.
3. **The AI Researcher:** Uses the platform to compare model outputs and study how different architectures handle complex logic instructions.

### User Stories
- *As a Participant,* I want to run my prompt against three different models simultaneously so I can identify which one interprets my physics instructions most accurately.
- *As a Participant,* I want to fork a public prompt from last month so I can iterate on its logic for this month’s theme.
- *As a Player,* I want to see a "Difficulty Badge" on a game so I know if I'm playing something generated by a "mini" model versus a flagship model.

## 4. Features
### 4.1 Core Features (MVP)
| Feature | Description | Acceptance Criteria |
| :--- | :--- | :--- |
| **One-Shot Engine** | Interface to input a single prompt and select 1-3 models for parallel generation. | No multi-turn chat allowed. Prompt is sent, and code is streamed to an isolated sandbox. |
| **The Sandbox** | An `iframe` environment that renders the generated HTML/JS/CSS. | Must support standard web APIs (Canvas, Web Audio). Must enforce monthly constraints (Lives, Score). |
| **Monthly Cycles** | Automates the lifecycle of themes, leaderboard freezes, and gallery archival. | New theme triggers every 1st of the month at 00:00 UTC. |
| **Model Tiers** | A categorization of models: Cheater (GPT-4/Opus), Normal (Kimi/GLM), Hard (Deepseek/Mini), Impossible (Tiny models). | Multipliers correctly applied based on the tier in the scoring algorithm. |
| **Scoring Algorithm** | Formula: `(AvgRating * HandicapMultiplier) + (1 / PromptLength) + Playtime`. | Real-time leaderboard updates based on these weighted variables. |
| **Public/Private Toggle** | Users decide if their prompt/evolution is visible immediately or at month-end. | Database stores visibility state; frontend hides source code accordingly. |

### 4.2 Future Features (Post-MVP)
- **Prompt Marketplace:** Tokenized exchange for "Base Templates" that are proven to generate stable game loops.
- **Prompt Jams:** 24-hour speed-run events with high-volatility multipliers.
- **Spectator Mode:** Live-stream of generations as they happen globally.

## 5. Technical Requirements
### Tech Stack
- **Frontend:** Next.js 16 (App Router) using React Server Components for performance.
- **API Layer:** tRPC v11 for end-to-end type safety between the frontend and database.
- **Database:** PostgreSQL 18 with Drizzle ORM for type-safe queries.
- **Authentication:** Better Auth (supporting GitHub/Email providers).
- **Styling:** Tailwind CSS v4 + shadcn/ui (Radix UI) for the retro-modern arcade aesthetic.
- **AI Orchestration:** Vercel AI SDK v6 for streaming responses and managing provider switch-cases.
- **Schema Validation:** Zod 4 for strict validation of prompt inputs and API responses.

### System Architecture
1. **Generation Isolation:** Generated game code must be sanitized and served through a scoped `iframe` on a separate subdomain to prevent XSS/Cookie theft.
2. **State Management:** Use `tRPC` hooks for data fetching; local state for the "Editor" experience using React state/context.
3. **Storage:** Prompts and generated code stored in Postgres (Text/JSONB). Large assets or snapshots stored in S3-compatible storage.

### Security & Performance
- **Prompt Injection Defense:** Sanitize outputs to ensure generated games cannot escape the iframe.
- **Rate Limiting:** Strict limits on generations per user per day to manage API costs and prevent leaderboard flooding.
- **Optimistic UI:** Leaderboard votes and prompt "likes" should use optimistic updates for a snappy feel.

- **Phase 1 (Week 1-2):** Infrastructure Setup. Next.js 16 scaffolding, Database schema with Drizzle, Better Auth integration.
- **Phase 2 (Week 3-4):** The Sandbox & Generator. Integration with Vercel AI SDK. Building the `iframe` runner and prompt-to-code pipeline.

## 7. Open Questions / Risks
- **Model Longevity:** What happens if a model version is deprecated? *Strategy: Snapshot the model name/version at the time of generation for the permanent gallery.*
- **Cost Management:** AI API costs could escalate. *Strategy: Implement a credit system or "User Provided API Key" (BYOK) for non-competitive runs.*
- **Code Malice:** One-shot prompts might generate infinite loops or crash browsers. *Strategy: Implement a "Report Game" feature and automated execution timeouts in the sandbox.*
